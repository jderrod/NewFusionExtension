# NewFusionExtension testing

NFE has two kinds of tests:

* **Unit tests** (`tests/test_*.py`): run without Fusion. The whole engine —
  including toolpath selection, posting, splicing, drilling and naming — runs
  against `FakeOps`, a simulated Fusion; the harness runs on a random port
  against a temporary project folder; the decision modules are compared
  exhaustively against ports of the old pipeline's code ("oracles").
* **Live tests** (`tests/live/run_order.py`): drop a real order into the real
  add-in running inside Fusion and check the result end to end.

Architecture background: [ARCHITECTURE.md](ARCHITECTURE.md). The selection
rules the tests protect: [tables/SELECTION_LOGIC.md](tables/SELECTION_LOGIC.md).

---

## 1. Running the unit tests

```
run_tests.bat
```

or

```
cd tests
py -3 -m unittest discover -p "test_*.py"
```

The tests need only the Python standard library. They create temporary
project folders (`tempfile.mkdtemp(prefix="nfe_test_")`), write
`api.addin_port = 59987` and a blank `cam.seed_counter_from` into their
sandbox config and start the harness HTTP server on port 0 (random), so they
never touch `dropbox/`, `output/`, `state/`, the running add-in (8766), a
running harness (8765) or the real program counter. The supervisor tests use
the process name `nfe_no_such_process.exe`, so no real process is ever
terminated. Tests that read the old pipeline's files (real G-code, drilling
and parameter exports) skip themselves when those folders are missing.

**Docs are part of the test run** (`tests/test_docs.py`): the catalogue below
must match the tests, the toolpath tables document must match the built-in
tables, ARCHITECTURE.md must mention every `nfe` module, and the SVG
diagrams must match `scripts/gen_diagrams.py`. After adding or changing tests
run `py -3 scripts/gen_test_catalogue.py`; after changing the flow update the
diagram data in `scripts/gen_diagrams.py` and run it.

### 3.2 `nfe/fake_ops.py`: the simulated Fusion

`FakeOps(files, save_ticks=2, spawn_hidden_copies=True, stubborn_closes=0,
fail_open=(), fail_export=False, not_ready_polls=0, resolve_failures=0)`
implements the `Ops` interface in memory; `ops.log` records opens, closes,
saves, workspace switches, generations and posts.

| Behaviour | Option | Real-world counterpart |
|---|---|---|
| Cloud saves complete asynchronously. | `save_ticks` | `doc.save()` returns while the upload continues. |
| Updating a drawing spawns a hidden copy of the model. | `spawn_hidden_copies` | Hidden reference documents (old project's leak). |
| `close_document` does nothing for the first N calls. | `stubborn_closes` | `Document.close()` returning `True` and doing nothing. |
| `ready()` false for the first N polls. | `not_ready_polls` | Fusion not signed in right after a restart. |
| `resolve_file` fails for the first N calls. | `resolve_failures` | Hub lookups failing while Fusion connects. |
| The next N model opens return the **previous** version. | `stale_opens` (attribute) | The hub handing out an old version right after a save (seen live, v1432 instead of v1434). |
| Toolpath generation completes after N polls; posts write Anderson-style `.nc` files (CRLF, `%`, `O####`, N-lines, `M30`) listing the active operations. | `generate_polls` (attribute) | `generateToolpath` futures, `CAM.postProcess`. |
| `open_document` / `export_pdf` raise. | `fail_open`, `fail_export` | Open or export failures. |

## 4. Live tests against real Fusion

### 4.1 `tests/live/run_order.py`

```
py -3 tests/live/run_order.py <order.json> [--timeout 1800] [--name <inbox file name>]
```

Prerequisites: Fusion running and signed in, the add-in answering on
`127.0.0.1:8766`, rules pointing at real models and drawings. The run saves

| Finding | Fix |
|---|---|
| Text parameters not detected (`Parameter.valueType` uses `adsk.fusion.ParameterValueTypes`). | `FusionOps._is_text` |

## 5. How to add a test

1. Pick the module: pure functions → `test_core.py`; decision tables →
   `test_cam_rules.py`; splicing → `test_gcode.py`; drilling →
   `test_drilling.py`; engine behaviour → `test_engine.py` or
   `test_cam_flow.py`; harness → `test_harness.py`; sync → `test_sync.py`.
2. Import `helpers` first (it sets `sys.path`), then the `nfe` modules.
3. For engine behaviour use a `Sandbox`, drop an order built with
   `helpers.order(...)`, configure `FakeOps` for the Fusion behaviour under
   test and drive the engine with `Sandbox.run`.
4. Give the test a docstring saying what it verifies, then run
   `py -3 scripts/gen_test_catalogue.py` so this document lists it
   (`test_docs` fails otherwise).
5. Always call `Sandbox.cleanup()` in `tearDown`.
